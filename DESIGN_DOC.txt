2.1 LoadingView (/loading)

| 기능 | 앱 시작 시 버전 확인, 필수 업데이트 체크 후 메인으로 이동 |

| 이탈 | pushReplacementNamed('/') → TitleView |

2.4 MainScreen (/main)

| 항목 | 내용 |

5. 새 곡 추가 시 수정해야 할 파일 분석
============================================================

5.1 필수 수정 파일 (반드시 변경)
--------------------------------
| 순서 | 파일 | 수정 내용 | 이유 |
|------|------|-----------|------|
| 1 | lib/data/song_registry.dart | SongRegistry.allSongs에 새 SongData 추가 | 곡 목록 등록 |
| 2 | assets/charts/{카테고리}/{곡명}.json | Python tools/beat_detector.py로 차트 생성 | 음악에 맞는 노트 데이터 |
| 3 | pubspec.yaml | assets/charts/에 새 카테고리 경로 추가 (있으면 생략) | Flutter가 차트 파일을 번들에 포함 |

5.2 선택적 수정 파일 (상황에 따라)
----------------------------------
| 파일 | 수정 내용 | 상황 |
|------|-----------|------|
| lib/services/stage_generator.dart | _generateFromChart에서 곡별 노트 수 조정 | 차트 길이가 기존 목표치와 다를 때 |
| lib/models/stage_model.dart | bpm 필드 갱신 | 새 곡의 BPM이 다를 때 (현재는 SongData에 있으므로 대부분 불필요) |
| lib/screens/stage_select_view.dart | 잠금 해제 로직이 stageNum 기반이면 추가 불필요 | 스테이지 번호가 기존 순서와 맞을 때 |
| lib/screens/lobby_tab.dart | recentStage 로직이 lastPlayedStageId 기반이면 추가 불필요 | 기본 동작 변경 없을 때 |
| assets/sounds/{카테고리}/{곡명}.mp3 | 실제 오디오 파일 추가 | 새 곡이 있을 때 |
| lib/providers/user_provider.dart | isStageOwned에서 새 스테이지 ID 추가 | 스테이지 잠금 해제 로직이 번호 기반일 때 |

5.3 수정 순서 요약 (새 곡 1개 추가 시)
--------------------------------------
Step 1: MP3 파일을 assets/sounds/{카테고리}/에 배치
Step 2: python tools/beat_detector.py input.mp3 output.json 실행
Step 3: assets/charts/{카테고리}/에 JSON 파일 이동
Step 4: song_registry.dart에 SongData 추가
Step 5: pubspec.yaml에 차트 경로 추가 (없으면)
Step 6: flutter pub get 실행
Step 7: 앱 실행하여 확인

5.4 SongData 생성 템플릿
--------------------------
SongData(
  id: 3,                                    // 기존 최대 id + 1
  title: '새 곡 이름',
  artist: '아티스트명',
  bpm: 140,                                 // 곡의 BPM
  audioPath: 'sounds/{카테고리}/새곡.mp3',   // MP3 파일 경로
  chartPath: 'assets/charts/{카테고리}/새곡.json',  // 차트 JSON 경로
  baseRewardCoins: 200,                     // 클리어 보상 코인
  baseNotes: [],                            // 차트 사용 시 빈 리스트 (미사용)
),

5.5 StageGenerator가 새 곡을 인식하는 메커니즘
----------------------------------------------
generateStage(stageNum, difficulty) 호출
  → SongRegistry.allSongs.firstWhere((s) => s.id == stageNum)
  → song.chartPath에서 JSON 파일 경로 추출
  → _beatCache[song.id]에서 차트 데이터 조회
  → 차트 존재: _generateFromChart()로 실제 비트 기반 노트 생성
  → 차트 없음: _generateOriginal()으로 기존 랜덤 생성 (폴백)



6. 핵심 데이터 모델 요약
============================================================

6.1 StageModel
--------------
class StageModel {
  int stageNumber;      // 스테이지 ID
  String title;         // 곡명
  String artist;        // 아티스트
  int bpm;             // BPM
  String difficulty;    // EASY/NORMAL/HARD
  int difficultyLevel;  // 난이도 레벨
  String audioPath;     // MP3 파일 경로
  List<NoteData> notes; // 노트 데이터 목록
  String rank;          // S/A/B/C/F
  int rewardCoins;      // 보상 코인
}

6.2 NoteData
------------
class NoteData {
  int timeMs;   // 노트 등장 시간 (ms)
  int lane;     // 레인 (0=D, 1=F, 2=J, 3=K)
}

6.3 SongData
------------
class SongData {
  int id;              // 곡 ID
  String title;        // 곡명
  String artist;       // 아티스트
  int bpm;             // BPM
  String audioPath;    // MP3 경로
  String? chartPath;   // 차트 JSON 경로 (있으면 차트 기반 생성)
  int baseRewardCoins; // 보상 코인
  List<NoteData> baseNotes;  // 미사용 (dead code)
}



7. 차트 JSON 스키마
============================================================

[1000, 1429, 1857, 2286, 2714, ...]

- 타입: List<int> (정수 배열)
- 값: 각 노트가 등장하는 시간 (밀리초)
- 첫 번째 값: 보통 1000 (게임 시작 1초 후)
- 간격: BPM에 따른 비트 간격 (예: BPM 140 → 약 428ms)



8. 난이도별 차트 활용 규칙
============================================================

| 난이도 | 차트 선택 방식 | 예시 (110개 차트) |
|--------|---------------|-------------------|

| NORMAL | 전체 사용 | 110개 노트 |
| HARD | 전체 + 보간 노트 추가 | 170개 노트 |

10. 서비스 및 데이터베이스
============================================================

10.1 DatabaseHelper (SQLite: taptoeat.db)
-----------------------------------------
테이블: users, owned_items, stage_results, quest_claims
주요 메서드: getOrCreateUser, addCoins, spendCoins, purchaseSong, purchaseEffect,
            equipItem, unequipItem, saveStageResult, getClearedCount, hasRankS,
            isQuestClaimed, claimQuest

10.2 UserProvider (ChangeNotifier)
----------------------------------
상태: _userId, _coins, _lastPlayedStageId, _ownedSongs, _ownedEffects,
      _equippedSongs, _equippedEffects
DB를 통해 영속화됨

10.3 SettingsProvider (ChangeNotifier)
--------------------------------------
상태: bgmVolume (0.8), sfxVolume (0.9), timingOffset (0.0)
SharedPreferences를 통해 영속화됨

메서드: loginProvider(), saveLoginProvider(), logout()



11. 노트 생성 시스템 상세
============================================================

11.1 기존 방식 (폴백)
----------------------
StageGenerator._generateOriginal()
- Random(42 + stageNum * 10 + level) 결정적 시드
- BPM 기반 고정 비트 그리드로 타임 계산
- random.nextInt(4)로 랜덤 레인 배정
- 난이도별 시간 간격 패턴:
  - EASY: 2번째 노트마다 half-beat
  - NORMAL: 4번째 노트마다 1.5-beat, 나머지 1/3-beat
  - HARD: 4번째 노트마다 half-beat, 나머지 quarter-beat

11.2 차트 기반 방식
-------------------
StageGenerator._generateFromChart()
- preloadCharts()로 앱 시작 시 모든 JSON을 메모리에 캐싱
- _beatCache[song.id]에서 차트 데이터 조회
- 난이도별 선택 방식:
  - EASY: 차트에서 2칸째 선택 (selectedIndex += 2)
  - NORMAL: 차트 모든 비트 순서 사용 (selectedIndex += 1)
  - HARD: 차트 모든 비트 사용 + 보간 노트 추가 (selectedIndex += 2, midBeat 계산)
- 모든 레인 배정은 random.nextInt(4)로 유지

11.3 경계 조건 (수정 후)
-------------------------
- HARD 모드에서 midBeat 계산 시 selectedIndex + 1 < chartBeats.length 조건으로
  범위 초과 방지
- selectedIndex >= chartBeats.length일 때 0으로 리셋 (사이클링)



12. 게임 플레이 핵심 로직
============================================================

12.1 노트 애니메이션
--------------------
RhythmGameWorld.onLoad(): NoteData → RhythmNoteComponent 변환 (초기 y=-999)
RhythmGameWorld.update(): targetTimeMs 기준으로 판정선까지 낙하
  - noteStartTime = targetTimeMs - fallDurationMs
  - progress = (currentMs - noteStartTime) / fallDurationMs
  - currentY = progress * judgeLineY

12.2 판정 시스템
-----------------
- 16ms 주기 _checkGameTick() 실행
- judgeMs > targetTimeMs + missGraceMs → MISS
- 플레이어 입력 시 _judgeTrack()으로 가장 가까운 미히트 노트 판정
- 판정 기준 (난이도별):
  - EASY: perfect 100ms, good 160ms, bad 240ms, missGrace 240ms
  - NORMAL: perfect 80ms, good 140ms, bad 210ms, missGrace 200ms
  - HARD: perfect 65ms, good 125ms, bad 200ms, missGrace 180ms
- 점수: PERFECT 300, GOOD 100, BAD 50
- 체력: PERFECT +4, GOOD +1.5, MISS -6, BAD -2.5

12.3 키 매핑
-------------
D(0) → track 0 (왼쪽)
F(1) → track 1
J(2) → track 2
K(3) → track 4 (오른쪽)
